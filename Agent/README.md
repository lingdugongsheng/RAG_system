
# 🤖 多代理智能客服系统

基于 **LangGraph + DeepSeek** 的意图驱动多 Agent 协作客服系统。支持意图分类与置信度评估、动态路由分发、四大专业 Agent 协作、回复质量检查与人工升级兜底。

---

## ✨ 核心特性

- **意图驱动的多 Agent 路由**：LLM 分类用户意图并计算置信度，低置信度自动降级至通用对话 Agent 二次确认，避免错误路由
- **四大专业 Agent 协作**：技术支持、订单服务、产品咨询、通用对话，各 Agent 绑定专属工具，职责边界清晰
- **工具调用体系**：订单查询、物流追踪、FAQ 检索、产品搜索、预算推荐，工具按领域分配，减少模型选择干扰
- **质量检查与兜底**：回复后独立质检节点从相关性、完整性、专业性、有用性四维度打分，低分自动追加人工转接提示
- **双通道人工升级**：用户主动要求转人工直接触发；系统质检低分自动触发；`already_escalated` 标记防止重复升级
- **FastAPI 服务化**：标准化 RESTful API，请求日志中间件、全局异常捕获、线程安全统计监控

### Agent 与工具绑定关系

| 技术支持 Agent | `search_faq` | 故障排除、使用帮助、FAQ 检索 |
| 订单服务 Agent | `query_order`, `track_shipping` | 订单查询、物流跟踪、退换货解答 |
| 产品咨询 Agent | `search_product`, `get_product_recommendations` | 产品搜索、功能咨询、预算推荐 |

```bash
pip install langchain langchain-openai langgraph python-dotenv fastapi uvicorn pydantic
```

在项目根目录创建 `.env` 文件：

```env
DEEPSEEK_API_KEY=your_deepseek_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

### 运行交互式 Demo

```python
from multi_agent import CustomerServiceSystem

system = CustomerServiceSystem()

# 单轮对话
result = system.handle_message("帮我查一下订单 ORD001", chat_history=[])
print(result["response"])
print(f"意图: {result['intent']}, 置信度: {result['confidence']:.2f}")
```

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

## 🔧 核心设计

### 1. 意图分类与置信度防御

`IntentClassifier` 使用 LLM 将用户消息分为五类：技术支持、订单服务、产品咨询、通用对话、请求升级。  
关键设计：**输出置信度分数**。置信度低于 0.6 时不直接路由到专业 Agent，而是交给通用对话 Agent 再次尝试理解——宁可多确认一句，也不答非所问。

### 2. 路由策略

使用 LangGraph 的 `Conditional Edges` 实现动态路由：

- `escalate` 意图 + 高置信度 → 直接走升级节点
- 其他意图 + 置信度达标 → 路由到对应专业 Agent
- 置信度不足 → 降级至通用对话 Agent

升级节点**跳过质量检查**直接返回——因为用户明确要求人工，不需要再评估。

### 3. 工具按领域分配

不是把所有工具塞给一个 Agent，而是按业务领域拆分绑定。  
好处：
- 工具列表短，模型选择准确率高
- 每个 Agent 的 System Prompt 可针对性设计
- 单个 Agent 出问题不会影响其他业务线

代价：架构稍复杂，需要前置路由。但意图分类本身的高可靠性使这个代价可控。

### 4. 质量检查与防重复升级

质检节点从四个维度百分制打分：相关性、完整性、专业性、有用性。

`already_escalated` 字段作用：  
质检节点在同一轮对话中可能被多次调用（如经过通用对话兜底后再质检），不加标记会导致每轮都追加转人工提示，回复内容堆满重复信息。加上标记后，**只会追加一次系统提示**。

### 5. 双通道人工升级

| 触发通道 | 条件 | 说明 |
|----------|------|------|
| 用户主动 | 意图为 `escalate` 且置信度 ≥ 0.7 | 用户明确说“转人工”、“我要投诉”等 |
| 系统触发 | 质检评分低或评估结果为需要升级 | 追加系统建议，保留原始回复 |

## 📊 API 接口

启动服务：

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

主要端点：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/health` | 系统健康检查 |
| `POST` | `/query` | 提交客服请求 |
| `GET` | `/history` | 获取当前对话历史 |
| `DELETE` | `/history` | 清除对话历史 |
| `GET` | `/stats` | 查看运行统计（总请求数、平均置信度等） |
| `POST` | `/reset` | 重置系统状态 |

### /query 请求体示例

```json
{
  "question": "我的订单 ORD001 到哪了",
  "use_history": true
}
```

### /query 响应体示例

```json
{
  "answer": "您的订单 ORD001（智能手表 Pro）已通过顺丰快递发货...",
  "intent": "order_service",
  "confidence": 0.92,
  "quality_score": 0.85,
  "escalated": false,
  "timestamp": "2026-06-01T14:30:00"
}
```

## 🎯 设计亮点

1. **分层防御体系**：意图置信度（前置过滤）→ 专业 Agent 处理（核心执行）→ 质量检查（后置兜底），三道防线逐级拦截异常
2. **通用对话兜底而非直接转人工**：降低人工成本，提升用户体验
3. **状态字段精细管理**：`already_escalated` 防止重复升级，`chat_history` 支持上下文理解
4. **全局异常捕获**：任何未预料的错误返回友好兜底回复，而非 500
5. **线程安全设计**：`threading.Lock` 保护全局单例和统计数据

## ⚠️ 当前局限与改进方向

| 局限 | 改进方向 |
|------|----------|
| 工具数据为模拟字典 | 接入真实 MySQL/PostgreSQL + 物流 API |
| 意图分类仅四类业务 + 升级 | 引入意图发现机制，自动识别新增高频意图类别 |
| 无用户身份认证 | 加入 JWT 认证，按用户隔离订单查询范围 |
| 对话历史仅内存存储 | 接入 Redis 持久化，重启不丢失上下文 |
| 缺少性能压测数据 | 用 Locust 做并发测试，确定单 worker QPS 上限 |

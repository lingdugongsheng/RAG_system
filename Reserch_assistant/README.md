## ✨ 核心特性

- **六阶段自动化流水线**：规划 → 收集 → 分析 → 综合 → 生成 → 检查，覆盖研究全流程
- **多源数据检索**：模拟学术数据库与网络新闻双源并发搜索，接口设计支持随时替换真实 API
- **自反馈迭代优化**：报告质量不达标自动返回收集阶段重新检索，最多迭代 2 次
- **结构化输出**：标题、摘要、引言、方法论、发现、分析、结论、建议、参考文献，完整学术格式
- **容错重试机制**：LLM 调用自带 3 次自动重试，避免临时网络故障中断整个任务
- **FastAPI 服务化**：标准化 REST API，请求日志中间件，全局异常兜底

## 🔬 六阶段研究流程

| 阶段 | 核心操作 | 产出 |
|------|----------|------|
| 1. 规划 | LLM 生成研究大纲、章节划分、关键问题列表、方法论 | 研究大纲 JSON |
| 2. 收集 | 学术数据库 + 网络新闻双源并发检索 | 原始资料列表 |
| 3. 分析 | LLM 提炼关键发现、支撑证据、置信度、信息空白 | 分析结果 + 来源摘要 |
| 4. 综合 | 为每个章节撰写 150-300 字草稿，标注引用 | 章节草稿字典 |
| 5. 生成 | 整合为完整 Markdown 报告，生成参考文献列表 | 最终报告文本 |
| 6. 检查 | 10 分制质量评估，低于 7.5 分触发重搜迭代 | 评分 + 改进建议 |

### 迭代触发与终止

| 条件 | 行为 |
|------|------|
| 评分 ≥ 7.5 | 输出最终报告 |
| 评分 < 7.5 且迭代次数 < 2 | 返回阶段 2，携带质量反馈重新检索 |
| 评分 < 7.5 且迭代次数 ≥ 2 | 强制输出，防止无限循环 |

## 🚀 快速开始

### 环境要求

- Python 3.10+
- DeepSeek API Key

### 安装依赖

```bash
pip install langchain langchain-openai langgraph python-dotenv fastapi uvicorn pydantic
```

### 配置

在项目根目录创建 `.env` 文件：

```env
DEEPSEEK_API_KEY=your_deepseek_api_key
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

### 运行示例

```python
from reserch_assistant import run_research

# 启动研究任务
result = run_research("人工智能在医疗诊断中的应用")

# 查看报告
print(result["final_report"])

# 查看统计
print(f"质量评分: {result['quality_score']}/10")
print(f"迭代次数: {result['iteration_count']}")
print(f"收集资料: {len(result['search_results'])} 条")
```

### 启动 API 服务

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

访问 `http://localhost:8000/docs` 查看 Swagger 文档。

## 🔧 核心设计

### 1. 规划先行

在执行任何检索之前，LLM 首先生成研究大纲。大纲包含：
- 报告标题与摘要
- 章节划分（引言、文献综述、方法、结果、结论等）
- 关键研究问题列表
- 拟采用的方法论

大纲为后续的检索和分析提供明确方向，避免盲目搜索无关资料。

### 2. 多源并发检索

| 数据源 | 模拟内容 | 可替换为 |
|--------|----------|----------|
| 学术数据库 | 计算机学报、Nature 等模拟论文 | Semantic Scholar API、arXiv API |
| 网络新闻 | 科技新闻网、环球时报等模拟文章 | Tavily Search API、SerpAPI |

两个数据源并发执行，结果合并后进入分析阶段。接口设计为 `search_academic_database(topic)` 和 `search_web(topic)`，替换真实 API 只需修改函数内部实现。

### 3. 自反馈迭代

质检节点用 LLM 对报告进行 10 分制评分，评估维度包括结构完整性、逻辑严谨性、引用准确性和学术规范性。

**迭代触发**：评分低于 7.5 分时，系统将质检反馈作为上下文，回到信息收集阶段重新检索补充资料，再走一遍分析 → 综合 → 生成 → 检查流程。

**终止保护**：最多迭代 2 次，超过后无论评分多少都强制输出，防止死循环。

### 4. 引用管理

生成报告时，LLM 被提示约束只能引用检索到的文献。参考文献列表从检索结果中自动提取格式化。生成后额外做一次校验检查引用是否存在。

### 5. 容错重试

所有 LLM 调用经过 `llm_call_with_retry` 包装，单次失败后等待 1.5 秒重试，最多 3 次。避免临时 API 波动中断整个研究任务。

## 📊 API 文档

### 端点总览

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/health` | 系统健康检查 |
| `GET` | `/stats` | 运行统计（总任务数、平均质量评分） |
| `POST` | `/research` | 启动研究任务 |

### `/research` 请求

```json
{
  "topic": "人工智能在医疗诊断中的应用"
}
```

### `/research` 响应

```json
{
  "topic": "人工智能在医疗诊断中的应用",
  "title": "人工智能在医疗诊断中的应用研究",
  "report": "# 人工智能在医疗诊断中的应用研究\n\n## 摘要\n...",
  "citations": [
    {
      "id": "[1]",
      "authors": ["张明", "李华"],
      "title": "深度学习在自然语言处理中的应用综述",
      "source": "计算机学报",

  "search_results_count": 6,

### 状态码说明

| 状态码 | 说明 |
|--------|------|
| 200 | 研究任务完成 |
| 422 | 请求参数校验失败（主题为空或过长） |
| 500 | 系统内部错误（已全局捕获，返回错误详情） |

## 🎯 设计亮点

1. **全流程自动化**：从主题到报告，无需人工干预
2. **自反馈闭环**：质量不达标自动回退重搜，具备自主纠错能力
3. **容错设计**：LLM 调用重试 + 安全 JSON 解析兜底 + 全局异常捕获，三重保障
4. **可扩展检索层**：模拟数据源可无缝替换为真实 API
5. **状态集中管理**：LangGraph State 贯穿全部六个阶段，每个节点输入输出可追溯

## ⚠️ 局限与改进

| 局限 | 改进方向 |
|------|----------|
| 检索数据为模拟字典 | 接入 Semantic Scholar、arXiv、Tavily 等真实 API |
| 引用可能含 LLM 编造信息 | 加检索后校验层，只允许引用系统内确实查到的文献 |
| 大纲生成后无人工确认环节 | 引入 LangGraph `interrupt` 机制，支持人机协作确认大纲 |
| 报告一次性输出，无中间调整 | 分阶段交互，用户可在分析阶段调整方向 |
| 缺少领域专业性评估 | 引入领域专家评分维度或 RAGAS 等自动化评估框架 |
